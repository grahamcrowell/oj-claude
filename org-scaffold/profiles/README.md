# Layout profiles

A project's `.claude/` state tree can take one of two shapes. Both are supported
first-class; neither is being deprecated. Pick by the size and shape of the
project, not by which looks more organized.

`oj-helper resolve-path <key>` is what makes the choice invisible to the skills:
they ask for a key, not a path. The profile decides what that key resolves to.

| | `flat` | `hierarchy` |
|---|---|---|
| Selected by | nothing — the default | `layout=hierarchy` in `.claude/oj-paths.env` |
| Backlog | one `BACKLOG.md` | one file per owning node, enumerated by `backlog-glob=` |
| Where a document goes | one `artifacts/` directory | the node that owns the subject, in the file named for its type |
| Category keys (`decisions`, `facts`, `open-questions`, `requirements`, `design`, `plan`) | unset — `resolve-path` exits 3 | resolve to `<node>/<type>.md` (or `<node>/facts/`) |
| Suits | a single project; one person or one team holding the whole picture | several sub-projects; a corpus too large for one person to hold at once |

## flat — the default, and the right answer more often than not

The current scaffold at the repo root **is** the flat profile: `BACKLOG.md`,
`artifacts/{adr,analysis}/`, `state/`, `reference/`, `llms.txt`. Nothing to
configure, no `oj-paths.env` needed.

A small project is genuinely well served by one `BACKLOG.md`. Do not adopt the
hierarchy because it looks more rigorous — a taxonomy imposed on a project that
does not need one costs real filing effort per document and returns nothing.

## hierarchy — when one file has stopped being one thing

Live under `hierarchy/` in this directory. Copy its contents into the project's
`.claude/` and edit the placeholders.

The signal to switch is not size alone; it is when a single file has stopped
answering a single question. A `BACKLOG.md` that has become several project
plans wearing one filename is the case this profile exists for: splitting it
per node makes each piece hold one subject, and `backlog-glob=` keeps the set
readable as one backlog.

**What you take on by switching:**

- **Ids must be globally unique across the whole file set**, not merely within
  a file. An id is the cross-reference key, so two items sharing one id make
  every inbound link resolve to whichever file is read first. Run
  `oj-helper backlog-lint` — it checks exactly this, plus duplicate anchors and
  within-file duplicates, all of which are invisible to a human reading the
  files.
- **Every document needs a filing decision**: classify by type, then write to
  that type's file at the owning node. See
  `${CLAUDE_PLUGIN_ROOT}/reference/file-patterns.md` § Filing Rule. Two rules
  decide the ambiguous cases: a review is not a design, and a fact needs
  provenance.
- **`artifacts` should stay unset.** Under this profile there is no dump
  directory by design. Setting `artifacts=` re-creates the folder the taxonomy
  exists to remove, and the skills will fill it.

## Switching later is cheap; switching back is cheap too

Both directions are a matter of writing or deleting `.claude/oj-paths.env` and
moving files. The plugin holds no state about which profile a project uses and
reads the answer fresh on every call, so there is no migration to run and
nothing to keep in sync. Start flat.
