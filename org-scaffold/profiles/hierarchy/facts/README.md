# Facts

Measured and derived statements about how the system actually behaves. One file
per domain: `aws-facts.md`, `cicd-facts.md`, `<domain>-facts.md`.

Resolve this directory with `oj-helper resolve-path facts` (add
`--node <relpath>` for a node-local facts area) rather than hardcoding the path.

## The provenance rule (required)

**Every row carries a provenance marker.** A number without one is not a fact;
it is a rumor with a decimal point.

| Marker | Meaning | What it obliges you to write |
|--------|---------|------------------------------|
| `MEASURED` | Observed directly | The exact command, query, or dashboard that produced it, and when |
| `DERIVED` | Computed from other facts | Which facts, and the computation |
| `ASSERTED-UNVERIFIED` | Believed but not checked | **The verification path** — the specific command or query that would settle it |

### Why the marker is not optional

An unmarked number is indistinguishable from a measured one. It gets cited, the
citation gets cited, and within a few weeks it is load-bearing without anyone
having checked it. The marker is what keeps that from happening silently.

**Prefer `ASSERTED-UNVERIFIED` with a stated verification path over a bare
number.** An unverified fact that says how to verify itself is useful and
honest. A bare number is neither, and costs more to undo than to never write.

**Never upgrade a marker without running the check that justifies it.**
Promoting `ASSERTED-UNVERIFIED` to `MEASURED` because it has been there a while,
or because it sounds right, is the single failure mode this rule exists to
prevent. Age is not evidence.

A skill appending a number here without a marker is producing a defect, not a
fact.

## Format

```markdown
# [DOMAIN] Facts

| Fact | Value | Provenance | Verified |
|------|-------|------------|----------|
| [what is being measured] | [value] | `MEASURED` -- `[the exact command or query]` | [YYYY-MM-DD] |
| [what is being computed] | [value] | `DERIVED` -- from [fact], [fact] | [YYYY-MM-DD] |
| [what is believed] | [value] | `ASSERTED-UNVERIFIED` -- verify with `[command that would settle it]` | -- |
```

## What does not belong here

- **Decisions** — a choice made, with its rationale, goes in `decisions.md`.
- **Open questions** — an unresolved question goes in `open-questions.md`. A
  question is not an `ASSERTED-UNVERIFIED` fact; the difference is whether you
  have a candidate answer.
- **Point-in-time findings** — a review of existing work goes to a history
  area. Facts here are meant to stay true, and are corrected rather than
  superseded.
